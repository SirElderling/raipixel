# PNG compression experiment register

Last reviewed: 2026-10-16. Scope: PR [#2](https://github.com/SirElderling/raipixel/pull/2), branch `feat/raster-foundation`. This is the **index of record** for hypotheses, measured candidates, regressions and follow-up gates. New work must **consult and update this file** before rerunning an algorithm that is already known to fail on the same codec and corpus.

The goal is the **smallest lossless interoperable PNG within bounded time and memory**, while retaining a separate fast writer. Experiments are diagnostics until promoted through correctness, memory/work accounting, and three-platform tests. The Rust `png 0.18.1` crate is used **only through its public interfaces as a black-box reference**. Never inspect/copy its implementation. Production implementation remains safe stable Rust 1.99.1 without new runtime dependencies.

## Fixed corpus and comparison rules

- `icon-64-compressed.png`: original four-color 64×64 case, SHA-256 `45c209032c94af8bd9ded7476f7c9839deb8520d164719a12856e2f54a7e88de`.
- `sheet-1024-compressed.png`: generated four-color sprite sheet, SHA-256 `4e329be91b53193666195066b19022a2e956f4895f616b5ebadb31d05375d44a`.
- `comparison-sheet-1024.png`: independently authored mixed-filter five-color sprite sheet, SHA-256 `b2212db9b942357462ccfefeb69b8312388738300aed2272b21fce24e7bf3d0a`.
- Additional coverage: incompressible 256-noise, textured 1024, odd scanlines (7×11, 13×11, 17×11, 257×7), 1024×300 crossing 65,535-byte DEFLATE chunks, 1/2/4/8-bit palettes, alpha-zero hidden RGB and >256 exact colors.
- Always compare actual PNG byte lengths, whole-encode times including palette building/output allocation, compiler, checksum verification, complete decoded RGBA including hidden RGB, determinism, negative CRC case, unsupported-image behavior, resource/work accounting and binary/heap impact. Calibrate at least 25 ms per timed batch, alternate/rotate samples, and report medians/ratios **per platform**. A reference default writer with better compression is **not** equivalent to its Fast mode.
- Independently ground each new accepted candidate using the public reference decoder before production promotion; the raipixel decoder alone is insufficient. `Work::remaining()` equality **does not prove** the candidate's extra scratch memory/CPU were realistically charged.
- Record script + Git commit SHA, input SHA, OS/CPU, rustc, source and driver hashes, trials, measured output, status, decision and unanswered safety questions. Keep the original raw CI logs linked. Never silently overwrite a prior measurement with a new environment's result.

### Fixed target and current gaps

Same indexed inputs: `png 0.18.1` default = **1,545 B** generated / **3,552 B** independent. The previous best experimental combined result is **2,308 B** (+49.4% over reference) / **4,074 B** (+14.7% over reference); this is **not yet a validated production candidate**. Quality-first compression may spend more milliseconds, but must honor deterministic bounded time/work/heap and must not create unacceptable pathological cases.

### Next experiment queue (ordered, change-controlled)

1. **Correct validation coverage** for C10 and C11, then collect native 3-OS evidence and write measured outcomes here. If new candidate fails exact RGBA/CRC/Adler, stop without benchmarking it.
2. **If C11 shows positive size gains**, screen an adaptive best-of-N policy: for each exact RGBA input, compare retained candidates, return the smallest and charge actual work. Include small palette, odd width, incompressible and cross-block cases.
3. **If depth reaches diminishing returns**, test one-step *cost-aware* LZ parsing using lengths/distances + actual Huffman code costs. Compare against C11 without changing filter/palette. Stop if no material size win.
4. Only then attempt a bounded, fallible-memory **production opt-in maximum encoder**, with fresh independent decoding tests and exhaustive preflight/resource accounting. No API/default behavior changes until this gate passes.

**Repetition guard:** Before coding, search this register and [the candidate notes](candidates/) for the same idea, compressor mode, corpus and search depth. Avoid duplicate runs on unchanged SHA/fixtures. If a trial is rejected, require a different causal condition (e.g. Sub *with dynamic Huffman* instead of Sub *with fixed Huffman*) and name that difference. Distinguish *queued*, *failed*, *rejected*, *promising*, *validated* and *promoted* statuses. Do not cherry-pick one file or one OS to make a generic claim.
