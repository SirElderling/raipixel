## Trade-off conclusions

Functionality versus code: PNG import, semantic state and correct animation metadata remain despite cost because correction and game integration otherwise fail. Simplicity versus extensibility: ordinary module extension replaces speculative plugin abstractions. Semantic components versus raster-only: named cels are the minimum distinction that preserves targeted edits. Compatibility versus native compactness: RPX is intentionally simple; PNG is the interoperability investment. Binary size versus maintainability: compiler profiles are measured after correctness; no unsafe/assembly/minimal-std engineering.

Several approaches eliminate entire subsystems: no second indexed raster backend; no input JSON parser; no model/HTTP client; no GUI/timeline; no packer; no effect graph; no script runtime; no undo database. Replay recipes are retained for creation/reuse but rejected as sole persistence because external assets and algorithms change. Shared transforms support components/frames/tiles, while frames with new art remain necessary. These are deliberate limitations, not claims of equivalence to every competitor workflow.
