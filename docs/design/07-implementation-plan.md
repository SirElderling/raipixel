# 7. Capability-driven implementation roadmap

S1 implementation has started; see [implementation status](../implementation.md) for delivered library functions. No milestone is accepted until its workflow gates pass. Deliver accepted workflows, not a broad feature-count commitment. Unsupported operations/fields report E_CAPABILITY with the actual supported set. Foundation is a usable static slice; **the first useful toolkit requires Foundation plus Core and scenarios A–E**, including animation. Advanced work is selected one workflow at a time.

| Slice | End-to-end usable result | Dependencies and acceptance gate |
|---|---|---|
| S1 Foundation: create or import, edit, inspect, persist, export | Create a recognizable small asset using a symbolic grid/basic drawing, OR read a real PNG; correct a selected region; preview; inspect/validate; save/reopen; export PNG+JSON | Domain/limits/errors + JSON + full required DEFLATE/PNG import and minimal writer are the critical path. Pass A/B/D and static E: independent decode, hidden-RGB/unaffected-state checks, snapshot state equality, invalid request/PNG publishes nothing. Run native cross-platform tests from this slice. |
| S2 Core: structured editing and reuse | Transfer an independently authored component into a layered project; mask/recolor/transform/stamp selected parts; preserve everything else; export editable snapshot and game frame | S1. Add masks, remaining geometry, exact transforms/grid reduction, styles/quantization and explicit multi-target edits. Pass mask/alias/COW/transfer-conflict tests and an equipment correction workflow; compare before/after state and registration. No rig or live references. |
| S3 Core: animation and controlled variations | Author or assemble a short animation, change one named component across frames, inspect motion diagnostics, export frames/sheet+timing/registration; produce a palette/seed-controlled asset family | S1/S2; depends on correct frame state and common renderer. Add clips/order/timing/anchors, sheet import/export/padding/extrusion, noise, contact/onion/diff. All A–E pass, plus six comparative tasks and a real independent game consumer. This is the first useful toolkit gate, not an assertion of measured advantage. |
| S4 Advanced: interoperability or richer production | Each increment completes one workflow: layered OpenRaster import/edit/export; APNG preview export; bounded grid analysis/correction; or an authored rectangular tileset/map with established metadata interchange | Only needed Core capabilities; no requirement to finish every Advanced item. Define exact subset, syntax/state versioning and independent fixtures first. Native state round trip, unsupported-feature rejection and consumer tests per increment. Tiles/maps need their domain/profile contract before implementation; PNG does not wait for them. |
| S5 Production maturity | Repeat Foundation/Core tasks reliably on clean macOS/Linux/Windows environments, with documented limits, format coverage, agent correction behavior and measured performance | Hardening is continuous from S1. Final gate deepens independent conformance/malformed corpus, resource/transport/path tests, packaging, real agent usability and documentation fidelity. Do not defer correctness until this slice or require all S4 candidates for it. |

JSON parser and PNG inflater can be developed/tested separately once image/error/limit contracts are stable, but S1 is not accepted until both workflows work together. Animation model fields are reserved and persisted from the initial schema; do not ship throwaway raw storage. Ordinary modules suffice; no detachable-backend machinery, optional external crate, plugin ABI or separate package graph in advance of demonstrated need.

## Tests and evidence required throughout

Use std-only `#[test]` and integration tests. Tests may invoke the built CLI with std::process; production never spawns a program. Independently authored expected rasters and licensed data fixtures are allowed, with provenance; copied decoder/algorithm implementations are not. External consumers/toolchains used for independent verification are optional verification facilities, never application/test-library dependencies. Checked-in fixtures and std tests must run offline without external executables beyond the Rust toolchain.

- Raster: exact lines/octants/reversed endpoints, shape boundaries, alpha/source-over vectors, same-target source snapshots, mask intersection, hidden samples, copy-on-write independence and transform identities.
- JSON: escapes/Unicode pairs, duplicate decoded keys, number grammar/integral ranges, truncations, unknown fields/versions, nesting and payload ceilings. Examples must match the structural schema and cross-field/owner rules.
- PNG: independent stored/fixed/dynamic/overlapping-reference cases; legal color/depth/filter/interlace matrix; sub-byte tRNS, Adam7 reset/stride, consecutive/empty IDAT; invalid trees/repeats/distances/window/checksums; expected decoded-length enforcement. A self-writer→self-reader round trip is insufficient.
- State/publication: all Core fields round-trip; reference conflicts, stale source changes, no external load dependencies, path traversal/symlinks; failure before rename leaves no destination; reporting failure afterward retains committed files. Low-limit fixtures exercise amplification without forcing actual OOM.
- Exports: exact fixed-grid coordinates, scaled pivots/anchors/component offsets, timing/playback/repeat, clipping/padding/extrusion, independently decoded samples and consumer placement.

Run native stable tests on aarch64-apple-darwin, x86_64-unknown-linux-gnu and x86_64-pc-windows-msvc; broaden target support based on demand. Compare canonical fixture bytes directly, not only CRCs. Record skipped OS capabilities honestly. Normal OS/CRT/toolchain facilities do not violate independence; test clean environments instead of promising universal static linking.

## Measure before committing

No credible fixed LOC, binary-size or completion-time commitment exists before the first integrated codec/authoring slice. Earlier whole-suite ranges are retired because they excluded the risk of the revised import-first path and treated unvalidated Advanced work as mandatory. This is an uncertainty statement, not a claim that implementation is cheap.

After S1, report subsystem size and engineering effort, time/memory for 16/32/64-pixel assets and a representative imported PNG corpus, snapshot file count/bytes, and parser/codec failures. After S3, report 64 frames × 8 layers at 64×64, 20 variants at 32×32, commands/tokens/corrections, game-consumer results and per-target executable size. Record machine/compiler/profile/input so results are reproducible. Set later performance budgets from those workloads; no arbitrary 2-second or executable-size gate is asserted now.

Each delivered increment needs passing relevant tests, rendered artifacts reviewed visually, updated capability discovery/docs, cargo fmt/test/clippy checks on stable, and no unresolved material contract defects. Broaden testing when new behavior or failures warrant it. Advance Advanced features only with a concrete task, benefit/cost evidence and a compatible preservation contract.
