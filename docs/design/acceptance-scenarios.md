These are release gates, not claims that implementation exists. “Supported” refers to selected M1–M6 design. Artist/agent supplies visual judgment and any missing poses/views/components. All compare original snapshot state to prove unaffected content survives.

## Failure gates and evidence

Every scenario also runs one invalid-input variant: duplicate owner; missing source component; malformed PNG; out-of-bounds edit; incorrect palette; invalid clip reference; inconsistent sheet dimensions; tile label mismatch; resource-budget exhaustion. Expected error code, target and corrective hint are specified. No pre-commit failure publishes a result, and no source snapshot changes. A deliberately broken stdout after publication preserves the committed directory and is documented as transport failure.

Visual approval is recorded separately from technical pass. The validation corpus includes sources produced by agents and by artists, plus hand-constructed rasters with known expected values. Licensing/provenance of contributed inputs must be recorded in test-fixture README; no claim to own imported art. Engine integration acceptance uses a minimal external game test scene to read PNG/JSON and verify timing, anchor placement, rect slicing and collision coordinates. That consumer is a verification artifact, not a runtime requirement of raipixel.

Success report for each scenario records target/compiler/profile, fixture IDs, functional check results, rendered artifacts, consumer outcome and elapsed times. Binary size and LOC are measured separately; an estimate is never substituted for a report.
